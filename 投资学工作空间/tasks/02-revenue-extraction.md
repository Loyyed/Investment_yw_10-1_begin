# 第二次任务合同：年报收入信息结构化提取

> [!important] 使用边界
> 本合同承接 Lec02 第一次任务。Agent 只能读取、定位、整理、提取线索和发现遗漏。候选记录必须由学生回到教师指定的年度报告原文核验，核验通过后才能进入阶段成果。

## 二、研究问题

年度报告按商品类型、经营地区或销售渠道披露了哪些收入与成本信息？如何把这些信息整理成字段统一、每一行都能回到原文复核的候选记录？

本任务只提取和整理信息：不计算增长率、毛利率或结构占比，不解释差异，也不判断商业模式、竞争优势或投资价值。

## 三、材料边界

### 允许使用

- 教师指定的年度报告 PDF：最终证据核验的依据；
- 同一年度报告的 Markdown：仅用于关键词搜索和候选定位；
- 第一次任务的 `work/notes.md`：检索路径、候选位置与人工修正；
- 第一次任务的 `work/pending-checks.md`：待核验线索、歧义和 `Unknown`；
- 第一次任务的 `outputs/first-analysis.md`：已核验内容与待处理问题；
- 第一次任务的 `evidence/evidence-log.md`：已经人工核验并取得编号的证据记录。

### 不能使用或修改的材料

- 不访问合同外的新闻、研报、数据库、网页或其他报告期材料；
- 不修改原始材料，不把空白、破折号与 `0` 相互替换；

## 四、过程底稿

将字段定义与候选记录写入：

```text
work/revenue-structure-extraction.md
```

每行分三步记录：

1. **是什么**：分解维度、项目名称、营业收入和营业成本；
2. **适用于什么范围**：报告期、单位与币种、报表主体和会计口径；
3. **如何复核**：来源位置、人工核验状态、当前判断状态和备注。

- **人工核验状态**：待核验 / 核验通过 / 核验未通过；
- **当前判断状态**：本任务只使用 `Fact` 或 `Unknown`，不在这一阶段写入 `Interpretation`、`Forecast` 或 `Decision`。

将检索路径、字段映射和人工修正写入：

```text
work/notes.md
```

将跨页、表头、单位、空白、同名项目、合计不符和口径冲突写入：

```text
work/pending-checks.md
```

课堂最小完成量：选择一个分解维度，完成至少 3 行候选记录、1 行人工核验记录，并保留至少 1 个待处理问题。

## 五、阶段成果

人工核验后的记录写入：

```text
outputs/revenue-structure-table.md
```

阶段成果必须区分已经核验的记录和仍为 `Unknown` 的内容，并保留分项与合计之间的对应关系。这份成果只作为下一步“指标口径识别”的输入，还不能直接写入 Lec03 的 `Fact` 栏。

其中，核验通过且可以标为 `Fact` 的记录，由学生按 `evidence/evidence-log.md` 的既有字段登记并取得证据编号。未通过核验或仍无法确认的内容，继续留在过程底稿中，并标为 `Unknown`。

## 六、验收

- [ ] 每行均可回到 PDF 的页码、表名、表头、行项目和必要脚注；
- [ ] 已核对报告期、单位、币种、报表主体和会计口径；
- [ ] 收入与成本没有跨列、跨行或跨表错位；
- [ ] 分项与合计的关系已经检查，差异没有被擅自修改；
- [ ] Agent 线索与人工核验结果明确分开；
- [ ] 核验通过的 `Fact` 已写入 `evidence/evidence-log.md` 并取得证据编号；
- [ ] 未解决问题保留在过程底稿并标为 `Unknown`；
- [ ] 没有在阶段成果中加入机制解释、预测、估值或投资建议；
- [ ] 执行人和复核人已签署。
