# Lec03 附件2

## 从年报证据到商业模式命题

> [!abstract] 本附件的任务
> 本附件补充 Lec02 与 Lec03 之间容易被忽略的一步。**找到数字后，先把信息整理成可复核的记录，再确认口径是否可比并核验变化。完成这些工作后，才能提出待核验的商业模式与竞争优势命题。**
>
> 本附件中的任务说明可直接用于年报研究工作台。它不预填任何公司的数字、页码或结论；凡是要标为 `Fact` 的内容，都必须由你回到教师指定的年度报告原文核验。

## 一、为什么不能从“找到数字”直接跳到“公司有优势”

在 Lec02，你已经练习过在限定材料中定位信息，并把 Agent 找到的内容保留为待核验线索。

但以下推理并不成立：

```text
找到营业收入
→ 计算出增长率
→ 认为需求改善或品牌增强
→ 认为公司具有竞争优势
```

中间至少缺少三道闸门：

1. **结构化提取**：散落在不同表格中的信息，是否已按统一字段逐行整理？
2. **口径识别**：两个数字是否属于同一报告期、单位、报表主体、合并范围和指标定义？
3. **变化核验**：在口径可比前提下，变化方向和幅度能否由原始材料复算？

> [!warning] 本课的边界
> 变化事实不等于变化机制。
>
> 经人工核验后，“营业收入上升”可以标为 `Fact`。至于它是否由价格上涨、品牌增强或竞争优势扩大造成，仍属于 `Interpretation`，必须补充证据，并接受反方证据检验。

## 二、Lec02 → Lec03 的任务接力

| 顺序 | 环节 | 要回答的问题 | 必须留下的阶段成果 | 这些成果还不能说明什么 |
| --- | --- | --- | --- | --- |
| 1 | 定位 | 信息在年报哪一页、哪张表、哪一行？ | 候选位置、候选数值、检索路径 | 找到位置，不代表内容已经核实 |
| 2 | 结构化提取 | 如何把多项披露整理为字段一致、可逐行复核的记录？ | 收入结构候选表 | 表格整理好了，不代表其中的数字可以直接比较 |
| 3 | 口径识别 | 指标名称相同或相近时，期间、单位、主体、合并范围与定义是否一致？ | 口径选择及其理由 | 明确口径后，仍不能据此解释变化原因 |
| 4 | 变化核验 | 在同一可比口径下，本期相对比较期发生了什么变化？ | 变化核验记录 | 确认发生了变化，仍不能据此认定变化机制 |
| Lec03 接力 | 命题形成 | 哪种收入、成本、资本投入、现金流或竞争机制，可能解释这项变化？ | 叙事—变量—证据矩阵中的待核验命题 | 提出命题，不代表命题已经得到验证，更不等于形成投资结论 |

开始下一项任务前，先读取上一项**经过人工核验**的阶段成果。需要使用其中的事实时，仍须回到年度报告原文复核；摘要不能替代原始证据。

> [!note] 与课程十二类任务的关系
> 本附件补齐的是“定位 → 结构化提取 → 口径识别 → 变化核验 → Lec03 命题形成”这条教学子链。
>
> “命题形成”只是本附件中的衔接步骤，不是十二类任务之外的新任务，也不代表主张已经核验完成。证据冲突、跨年度比较和完整的主张核验，留到后续任务继续训练。

## 三、所有任务都使用同一份五项任务合同

开始操作前，先写清以下五项。它们不能因为任务变简单而被省略。

| 任务合同要素 | 你必须写清什么 |
| --- | --- |
| **研究问题** | 本次真正要回答的具体问题，而不是泛泛的“分析公司” |
| **材料边界** | 可以使用哪些材料、对应什么版本和报告期；哪些材料不能使用；现有材料还不能支持哪些结论 |
| **过程底稿** | 候选位置、字段、计算、修正、冲突与 `Unknown` 保存在哪里 |
| **阶段成果** | 人工核验后交出什么、采用什么格式、保存到哪里 |
| **验收** | 怎样证明每条记录都能回到原始材料复核，怎样区分 `Fact`、`Interpretation` 与 `Unknown`，以及由谁作出最终判断 |

“材料边界”既要写允许使用的材料，也要写禁止事项。“验收”既要写证据核验要求，也要写完成条件。过程底稿不能省略；阶段成果也不等于最终投资结论。

## 四、任务二：年报收入信息结构化提取

> [!tip] 学生执行文件
> 使用[第二次任务合同：年报收入信息结构化提取](../学生用/第二次任务合同_年报收入信息结构化提取.md)。本节用于理解为什么这样做，合同单用于实际执行、签署与验收。

### 1. 研究问题与材料边界

以教师指定的公司年度报告为唯一原始材料，把收入与成本披露整理为一张字段稳定、可逐行核验的候选表。

本任务只做**提取与整理**，不做解释：

- 不计算增长率、毛利率、结构占比或其他衍生指标；
- 不解释收入差异，不判断商业模式或竞争优势；
- 不把空白、破折号与 `0` 相互替换；
- 不因名称相近而合并不同主体或不同口径的项目；
- Agent 的输出只是一条待核验线索，不能直接成为 `Fact`。

### 2. 课堂最小完成量

- **建议用时**：25 分钟；
- 每组选择商品类型、经营地区或销售渠道中的一个分解维度；
- 在表中完成至少 3 行候选记录；
- 完成至少 1 行人工核验记录；
- 至少发现并保留 1 个表头、跨页、空白、单位或口径问题。

课后再由小组合并三个分解维度，完成合计检查与完整阶段成果。评分看核验质量，不看填写行数。

### 3. 先固定字段，再填写数值

先在下列过程底稿中定义字段和记录候选：

```text
work/revenue-structure-extraction.md
```

| 字段 | 填写要求 |
| --- | --- |
| 分解维度 | 商品类型 / 经营地区 / 销售渠道 |
| 项目名称 | 按原表用词记录，不改名、不合并 |
| 营业收入 | 保留原始数值；未披露时留空并说明 |
| 营业成本 | 保留原始数值；未披露时留空并说明 |
| 报告期 | 区分本期、上期及具体年度 |
| 单位与币种 | 按原表记录，不默认换算 |
| 报表主体 | 明确是公司、集团或其他主体 |
| 会计口径 | 合并财务报表 / 母公司财务报表 / 尚待确认 |
| 来源位置 | PDF 页码、报告页码、章节、附注或表名 |
| 人工核验状态 | 待核验 / 核验通过 / 核验未通过 |
| 当前判断状态 | 本任务只使用 `Fact` 或 `Unknown`，不在这一阶段写入解释、预测或决策 |
| 备注 | 脚注、空白、转换错误或待复核事项 |

### 4. 用 Agent 时，人与 Agent 分工不变

Agent 只能做五件事：**读取、定位、整理、提取线索、发现遗漏**。

你必须自己做四件事：**定义问题、限定材料、核验证据、承担判断**。

如果同名表格同时出现在合并财务报表和母公司财务报表中，应把两者都列为候选并记录差异，不能不作说明就直接选用其中一张。

### 5. 核验与交付

检索路径、字段映射、人工修正和遗漏写入：

```text
work/notes.md
```

表格跨页、单位不明、合计不符、同名项目或口径冲突写入：

```text
work/pending-checks.md
```

人工核验后的阶段成果统一写入：

```text
outputs/revenue-structure-table.md
```

其中，核验通过且可以标为 `Fact` 的记录，应按 `evidence/evidence-log.md` 的既有字段登记并取得证据编号。未通过核验，或原始材料仍不足以作出判断的内容，继续留在过程底稿中，并标为 `Unknown`。

提交前逐行检查：

- [ ] 已核对 PDF 页码与报告页码、表名、表头和脚注；
- [ ] 已核对报告期、单位、币种、报表主体与会计口径；
- [ ] 已核对收入与成本没有跨列或跨行错位；
- [ ] 已记录各分解维度的分项与合计是否对应；
- [ ] 未解决的提取异常和口径问题仍保留为 `Unknown`；
- [ ] 阶段成果只作为下一步“口径识别”的输入，还不能直接写入 Lec03 的 `Fact` 栏。

## 五、任务三：年报指标口径识别

> [!tip] 学生执行文件
> 使用[第三次任务合同：年报指标口径识别](../学生用/第三次任务合同_年报指标口径识别.md)。

### 1. 研究问题与材料边界

这一任务训练一句纪律：**先识别口径，再使用数字。**

在第二次任务形成的候选收入结构表中，找出名称相近但可能不可比的收入与利润指标，比较其口径并说明取舍理由。例如：

- 营业总收入、营业收入与利息收入；
- 合并利润表与母公司利润表中的同名收入指标；
- 合并财务报表附注与母公司财务报表附注中的收入、成本分解表；
- 净利润、归属于母公司股东的净利润与母公司净利润。

本任务不计算变化幅度，不解释经营原因，不评价商业模式、竞争优势或投资价值。

### 2. 课堂最小完成量

- **建议用时**：25 分钟；
- 每组完成 1 组收入口径冲突和 1 组利润口径冲突；
- 至少保留 1 条“初选错误 → 发现冲突 → 回到原文 → 修正口径”的完整记录；
- 能够依据指标边界、报表主体、报告期、单位、会计口径和研究用途说明采用或排除理由；
- 仍然无法确认时，保留为 `Unknown`。

### 3. 建立候选口径清单

每个候选指标单独成行，保存至：

```text
work/metric-scope-candidates.md
```

| 字段 | 填写要求 |
| --- | --- |
| 候选编号 | 为每个候选值分配唯一编号 |
| 原文指标名称 | 按原表记录，不擅自改名 |
| 候选数值 | 保留原始数值，不在此换算 |
| 指标边界 | 它包含什么；无法确认时记 `Unknown` |
| 报表主体 | 公司、集团或其他明确主体 |
| 会计口径 | 合并财务报表 / 母公司财务报表 / 尚待确认 |
| 报告期或时点 | 本期、上期、期末、期初及具体年度 |
| 单位与币种 | 按原表记录 |
| 报表与附注 | 财务报表名称、附注编号、表名或章节 |
| 来源位置 | PDF 页码、报告页码及可复核定位 |
| 与研究问题的关系 | 可能采用 / 可能排除 / 尚待确认 |
| 人工核验状态 | 待核验 / 核验通过 / 核验未通过 |
| 当前判断状态 | 本任务只使用 `Fact` 或 `Unknown`，不在这一阶段写入解释、预测或决策 |

### 4. 根据研究用途选择口径

经过人工核验后，在下列文件中记录采用、排除与 `Unknown`：


| Lec03 研究用途 | 采用的候选编号 | 采用理由 | 排除的候选编号及理由 | 仍未解决的 `Unknown` | 人工签署 |
| --- | --- | --- | --- | --- | --- |
| 描述集团收入总体规模 |  |  |  |  |  |
| 描述集团收入的商品类型结构 |  |  |  |  |  |
| 描述集团收入的经营地区结构 |  |  |  |  |  |
| 描述集团收入的销售渠道结构 |  |  |  |  |  |
| 描述归属于母公司股东的净利润 |  |  |  |  |  |

选择或排除候选指标时，理由必须来自指标边界、报表主体、报告期、单位、会计口径、来源位置或研究用途。以下说法都不能作为理由：

- 数值看起来正确；
- 数字彼此接近；
- Agent 推荐；

### 5. 形成口径卡并交接 Lec03

经人工核验并确认的口径卡写入：

## 六、任务四：从口径识别进入变化核验

> [!tip] 学生执行文件
> 使用[第四次任务合同：年报指标变化核验](../学生用/第四次任务合同_年报指标变化核验.md)。

先完成结构化提取并明确指标口径，再由学生回到原文核验。三步都完成后，才能选择一个指标核验其变化。

### 1. 先检查能否比较

常用的同比变动幅度为：

```text
变动幅度 =（本期数 − 比较期数）÷ 比较期数
```

算出结果不等于完成核验。遇到以下任何一种情况，应立即**停止计算**，回到口径识别记录重新检查：

- 比较期数为零；
- 指标定义发生变化；
- 合并范围发生变化；
- 单位或币种不同；
- 前期数据被重述；
- 不能确认两期是否属于同一口径。

如果无法可靠调整，就应保留为 `Unknown`，不能用“估计可比”代替核验。

### 2. 过程底稿与阶段成果

候选值、公式、冲突与修正统一写入：

```text
work/change-verification.md
```

人工核验后的正式记录写入：

```text
outputs/change-verification-record.md
```

| 字段 | 填写要求 |
| --- | --- |
| 指标名称 | 使用年报正式名称，不改写为近义词 |
| 本期数与报告期 | 原始数值、报告期和精确定位 |
| 比较期数与比较基数 | 上年同期、上年末或其他明确基础 |
| 单位 | 两期单位必须一致；如有换算，保留过程 |
| 口径 | 合并、母公司、分部或其他适用口径 |
| 原文限制 | 重述、合并范围、会计政策与脚注等限制 |
| 计算 | 公式、代入值、结果与舍入规则 |
| 当前状态 | `Fact` 或 `Unknown`，并说明原因 |
| 人工核验 | 核验人、核验位置与修正内容 |

核验通过且可以标为 `Fact` 的变化记录，应同步登记到 `evidence/evidence-log.md` 并取得证据编号。已经停止计算或仍无法确认的记录，应继续保留为 `Unknown`。

## 七、Lec03 输入包：把事实带入证据矩阵

> [!tip] 学生执行文件
> 使用[Lec03 任务合同：商业模式与竞争优势证据表](../学生用/Lec03任务合同_商业模式与竞争优势证据表.md)。

完成前三项任务后，按下表整理 Lec03 的输入材料。除了信息披露地图和证据账本，还须带入已经人工核验的收入结构、指标口径和变化记录。

| Lec02 阶段成果 | 在 Lec03 中的用途 |
| --- | --- |
| `outputs/revenue-structure-table.md` | 叙事—变量—证据矩阵中的已核验事实和价值驱动变量候选 |
| `outputs/metric-scope-decision.md` | 每个数字的适用范围、使用限制，以及被排除的口径 |
| `outputs/change-verification-record.md` | 提出机制假设时可以使用的事实依据，但它本身不能说明变化机制 |
| `evidence/evidence-log.md` 中的证据编号 | 管理层表述和 `Fact` 的原始材料指针 |
| `Unknown` 清单 | 待核验问题、合理替代解释和反方检查的入口 |

凡是没有明确口径、未经人工核验，或无法指向原始材料的记录，都不能标为矩阵中的 `Fact`。

填写过程中的候选叙事、变量和待核验问题写入：

```text
work/lec03-claim-notes.md
```

经人工核验、可带入课堂成果的矩阵写入：

```text
outputs/lec03-evidence-matrix.md
```

### 叙事—变量—证据矩阵的扩展字段

| 字段 | 你要回答的问题 |
| --- | --- |
| 管理层表述 | 公司原文怎样描述收入、客户、渠道、品牌、成本或行业位置？ |
| 原始材料与版本 | 表述来自哪份批准材料、哪个版本？ |
| 精确定位与证据编号 | 表述和事实各在何处，对应哪条 evidence-log 记录？ |
| 已核验事实 | 写明本命题依据哪项已核验的财务、经营、行业或制度事实。若使用指标变化，还须确认两期口径一致，并已完成变化核验。 |
| 机制假设 | 价格、销量、产品结构、成本、资本投入、现金流或竞争位置中的哪条路径，可能解释这项变化？ |
| 可观察变量 | 若机制成立，还应观察到什么方向、时点和口径的结果？ |
| 优势来源与模仿壁垒 | 如涉及竞争优势，它属于哪类来源，竞争者为什么难以复制或替代？ |
| 合理替代解释 | 哪些其他机制也能解释现有变化？ |
| 反方证据 | 什么事实会推翻或显著削弱命题？ |
| 支持边界 | 现有证据最多能说明什么？还有哪些结论不能据此得出？ |
| 当前状态 | `Fact` / `Interpretation` / `Forecast` / `Decision` / `Unknown` |
| 后续验证 | 哪项留给 Lec04—05 的财务结果继续检验？ |

> [!important] 五种状态不能混用
> - 管理层**说过**某句话，可以是 `Fact`；
> - 管理层所说的机制**真实成立**，不能因此自动成为 `Fact`；
> - 证据不足的机制应标为 `Interpretation` 或 `Unknown`；
> - 本课不根据这些命题直接作出买入、卖出等 `Decision`。

本课共提交五项阶段成果：

1. 业务与行业问题清单；
2. 叙事—变量—证据矩阵；
3. 商业模式经济逻辑图；
4. 竞争优势证据要求表；
5. 两项人工核验记录：一项记录经过核验、可以标为 `Fact` 的内容；如有必要，可在此基础上写出 `Interpretation`。另一项记录因证据不足而保留为 `Unknown` 的内容。

矩阵连接叙事、变量和证据；经济逻辑图呈现“收入 → 成本 → 资本投入 → 现金流”；竞争优势证据要求表按照“优势来源 → 影响机制 → 可观察结果 → 模仿壁垒 → 反证条件”展开。

## 九、观察性拓展：何时把任务方法提炼成项目级 Skill

> [!note] 不计分拓展：时间盒与提交边界
> 本节是课后观察材料，不计分。建议课堂用时 **10—15 分钟**：从一次真实错误中提炼一条稳定规则，再设计一组“应该触发”和“不应触发”的测试。
>
> 本节不属于本课五项阶段成果，不要求提交完整 Skill 工程。上一节的一行专业命题记录只是叙事—变量—证据矩阵的课堂最小完成量，不能替代其他阶段成果。

### 1. Skill 固化什么，不固化什么

| 可以提炼为稳定流程 | 必须留在本次任务合同或原始材料中 |
| --- | --- |
| 先读取项目规则和本次任务合同 | 公司名称、证券代码、报告年度 |
| 定位 → 结构化提取 → 口径识别 → 变化核验 | 本次允许使用的具体文件和时点边界 |
| 必填字段与缺失字段检查 | 未经核验的数字、页码与表格答案 |
| 原始材料只读，线索与证据分开 | 本次研究问题和输出路径 |
| 发现口径冲突时停止并保留 `Unknown` | 收入变化原因、商业模式或竞争优势判断 |
| 完成后报告已定位、已核验、待核验与遗漏 | 预测、估值与买卖建议 |

Skill 不替代任务合同。每次新任务仍需重新写明五项：研究问题、材料边界、过程底稿、阶段成果、验收。

### 2. 什么时候才值得开发 Skill

在以下四个问题都有答案前，不急着开发：

1. 这套步骤是否已经在多轮真实任务中使用，而非只是在纸面上看起来合理？
2. 人工核验发现过哪些错误，这些修正是否已经进入稳定流程？
3. 换一家公司、年度或指标后，哪些步骤仍然不变？
4. 哪些内容一旦固化，反而会把旧数字、旧口径或旧判断带入新任务？

### 3. 项目级 Skill 的最小结构

教师演示可以参考 Claude Code 官方 `plugin-dev` 中的 `skill-development` 方法，依次完成：**具体样本 → 稳定流程 → 最小结构 → 测试 → 迭代**。

这里的 **skill-dev** 只是课堂简称，不是斜杠命令或终端命令。系统根据 `description` 和请求语义决定是否加载相关 Skill。

学生在年报研究工作台中制作的是**项目级 Skill**，而非完整 plugin。最小目标位置为：

```text
.claude/skills/<skill-name>/SKILL.md
```

没有安装 `plugin-dev` 时，仍可按同一流程手工完成，评分标准不变：整理样本、提取稳定步骤、写最小 `SKILL.md`、检查触发条件、在新任务测试、根据错误迭代。

### 4. 教学用最小骨架

下面只展示结构。不要把公司的数字、页码、材料范围或结论预填进 Skill。

```markdown
---
name: annual-report-metric-verification
description: This skill should be used when the user asks to "extract comparable annual-report metrics", "identify reporting scope or units", or "verify year-over-year changes from an annual report".
---

# 年报指标提取与变化核验

## 任务边界

- 读取项目规则和本次任务合同，确认目标、批准材料、读写范围、输出和验收。
- 只使用任务合同批准的原始材料，不修改原始材料。
- 将 Agent 输出标为待核验线索，不自行宣布证据核验通过。
- 不解释经营原因，不形成商业模式、竞争优势、估值或投资结论。

## 执行流程

1. 定位指标所在的报告、报表、页码、行项目和必要脚注。
2. 按统一字段提取本期数、比较期数、单位、报告期和口径。
3. 检查指标定义、合并范围、比较基数、重述和单位是否一致。
4. 仅在口径可比时计算变化；不可比时停止计算并记录 `Unknown`。
5. 输出候选记录、缺失字段、冲突与人工核验清单。
```

> [!warning] 自动化的边界
> 检查脚本只能发现字段遗漏、格式错误或公式问题。它不能证明记录与原文一致，也不能替你选择口径、解释机制或作出投资判断。
