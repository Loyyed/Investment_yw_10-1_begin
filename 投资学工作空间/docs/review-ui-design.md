# 简化核验逻辑与维护说明

用户入口为根目录人工核验入口.cmd。窗口打开与默认选择均不写入确认；只有本人点击确认，才将所选候选写为Fact。窗口也支持Unknown、撤回及独立的第四次可比性核验。

## 唯一记录与派生视图

- evidence/review-state.json保存本人确认、候选与来源指纹、时间、口径及历史事件。
- evidence/confirmed-facts.json是给后续研究用的有效Fact导出；Markdown账本和状态表是便于阅读的同步视图。
- 后续Agent读取scripts/review_store.py的ReviewStore(...).facts()，核对当前候选与原PDF，避免把旧导出当作最新有效确认。
- 指定PDF或候选改变后，旧记录保留历史，但对当前版本返回Unknown，需要本人重核。
- 原始work/structured-data.json继续保存机器提取状态；人工确认不覆写原件，不替签复核，不自动关闭合同。

## 可靠性与保护

主记录原子保存；同步中断可以重试刷新。记录重复确认保持幂等，撤回留历史。同步使用受管理的区块或状态列，保留正文与手写内容。

提交同时携带窗口展示时的候选指纹和PDF哈希，保存锁内再次比对；来源发生变化时整批拒绝，重新加载后由本人核对。可比性展示和计算使用同一快照，并比对原始值、规范值及有效Fact，避免对旧展示确认新数据。

旧生成脚本检查核验历史和config/generation-baseline.json；即使人工修改已经提交Git，或工作空间没有Git，仍会停止重建，保留填写。第四次复算要求当前来源一致的独立可比性确认，不以第一次完成代替。

原件位置单独存于config/workspace.json；工作空间位置由脚本自身确定。合同检查允许填写空栏、签署与验收标记，继续验证材料和使用边界等实质条款。

work/review-ui-upgrade-backup/存放本次升级前文件，属于本机恢复资料，不进入Git。升级保留用户原来已填写的第一次合同及未提交改动。
